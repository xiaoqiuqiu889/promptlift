# Prompt Lift 微信-like 界面五轮自主优化报告

## 目标

在不改变“Windows 任意输入框里的安全表达助手”定位、不增加内容历史与社交数据负担的前提下，把 Prompt Lift 的扩展界面升级为更接近成熟微信类产品的信息架构、视觉语言和操作路径。

## 产品边界

- 保留小精灵单击和双击 Alt 的零选择高频入口。
- 保留 AI 提示词、向上沟通、用户沟通、PPT 文案四种表达场景。
- 保留四档模型优化、审阅后应用、CAS 安全回填、模型配置和小精灵选择。
- 不照搬聊天、朋友圈、支付和小程序。它们与安全文本处理定位无关，也会引入账号、历史、社交图谱、支付合规等新的隐私与架构项目。
- 将微信类产品的成熟经验转译为：四区导航、分组列表、父子页面、克制绿色、清晰状态和低学习成本。

## 基线诊断

1. 原界面把档位、模式、小精灵、模型、检查、自启动和退出放进同一长菜单，功能虽然齐全，但缺少稳定心智模型。
2. 子设置页与父菜单同时纵向堆叠，小窗口需要反复滚动，返回关系不够清晰。
3. 扩展界面已使用浅色与绿色，但旧样式仍保留较多卡片感，缺少统一的列表行高、分隔线和底部导航节奏。
4. 当前模式、档位、应用方式散落在多处，用户不能在进入设置后快速确认完整状态。
5. 安全能力存在于底层实现，却没有简洁、可发现的用户说明。

## Loop 1：从长菜单升级为四区信息架构

### 具体改动

- 新增“处理 / 场景 / 服务 / 我的”四个一级入口。
- “处理”集中显示优化档位、工作模式、审阅后应用。
- “场景”直接展示四种表达对象，选择后留在当前页确认状态。
- “服务”集中模型与 Key、模型检查、开机自启动、安全说明。
- “我的”集中产品身份、小精灵偏好和退出。

### 理由

用户无需记住一串并列设置，只需先判断“我正在处理什么、我要换场景、我要检查服务，还是修改偏好”。

### 效果评估

- 四个一级入口均有独立页面与明确归属。
- 没有引入与产品定位无关的社交或支付模块。
- 契约：`test/wechatLikeUi.contract.test.mjs` Round 1。

## Loop 2：统一极简扁平视觉语言

### 具体改动

- 使用 `#f5f5f5` 中性底色、白色内容面与 `#07c160` 克制绿色强调。
- 列表行统一为至少 48px，高频入口的触达范围更稳定。
- 使用 1px 分隔线、8px 组圆角和扁平选中态。
- 底部导航固定为四等分，图标保持单色，不复制任何品牌资产。
- 去除扩展窗口气泡尖角；继续禁止渐变、重阴影与装饰性动效。

### 理由

成熟感来自一致的层级、间距和反馈规则，而不是增加视觉装饰。

### 效果评估

- 360×520 至 640×760 四档扩展窗口均无横向越界。
- 视觉审计未发现渐变、阴影或几何缺陷。
- 契约：`test/wechatLikeUi.contract.test.mjs` Round 2。

## Loop 3：重做父子页面与返回路径

### 具体改动

- 打开档位、模式、小精灵、模型或说明时，子页替换父页，不再叠在长菜单下方。
- 子页返回时恢复进入前的一级入口。
- 档位、模式和小精灵选择后返回父页，并立即展示更新后的状态。
- 浏览功能中心时暂时隐藏任务结果区；任务数据仍在内存中，退出功能中心后不丢失。

### 理由

一个屏幕只承担一个主要任务，用户可以自然理解“进入—选择—返回”，小窗口也无需穿过两层内容。

### 效果评估

- 360×520 截图中顶部身份、当前页面和底部导航同时完整可见。
- 设置子页与任务页互斥显示，避免滚动裁切小精灵或结果编辑器。
- 契约：`test/wechatLikeUi.contract.test.mjs` Round 3。

## Loop 4：补齐定位内的功能完整性

### 具体改动

- “处理”页新增场景、档位、应用方式三项实时总览。
- “服务”页增加安全与使用说明。
- 明示三项安全承诺：不保存输入内容或优化历史、应用前校验目标窗口与原文、API Key 使用 Windows 加密存储。
- “服务”和“我的”保留自启动、小精灵等状态的无障碍实时文本。

### 理由

微信类成熟体验不仅是导航，还包括用户能随时确认当前状态，并能理解关键能力为什么可信。

### 效果评估

- 模式、档位、审阅方式、小精灵和自启动变化会同步刷新总览。
- 新功能仅解释已有真实能力，没有制造历史、云同步或自动发送等不存在的承诺。
- 契约：`test/wechatLikeUi.contract.test.mjs` Round 4。

## Loop 5：可访问性、反馈与小窗口收口

### 具体改动

- 底部入口使用 `tablist / tab / tabpanel` 语义。
- 同步 `aria-selected`、`aria-pressed`、`aria-checked` 和键盘焦点。
- 支持左右方向键循环切换四个一级入口。
- 保留清晰的 `focus-visible`，并遵循系统“减少动态效果”设置。
- 基于第一次真实截图继续迭代：功能中心改为占满扩展窗口剩余高度，底部导航真正落在窗口底部。

### 理由

最后一轮重点解决“测试通过但画面仍不够成熟”的细节，使鼠标、键盘和小窗口体验保持一致。

### 效果评估

- 五轮 UI 契约全部通过。
- 全量自动化测试通过。
- Electron 视觉 QA 覆盖四种窗口尺寸、四种模式、四个档位、三种小精灵、审阅与错误状态；最终产品缺陷为 0。
- 合成拖动/缩放仍记录为自动化限制，不计入产品缺陷；对应底层行为另有自动测试保护。

## 最终信息架构

| 一级入口 | 核心任务 | 主要功能 |
| --- | --- | --- |
| 处理 | 确认本次如何优化 | 当前状态、优化档位、工作模式、审阅后应用 |
| 场景 | 切换表达对象 | AI 提示词、向上沟通、用户沟通、PPT 文案 |
| 服务 | 保证模型和系统可用 | 模型与 Key、连接检查、自启动、安全说明 |
| 我的 | 管理个人偏好 | 产品身份、小精灵、退出 |

# Prompt Lift「一起让表达变好」验收报告 v1.3

## 1. 验收范围

对应 [优化方案](../docs/expression-quality-optimization-v1.3.md) 中的模型协议、提示词边界、界面文案、结果摘要、回归测试和视觉表现。验收对象为当前工作区源码，不包含重新打包 Windows EXE。

## 2. 逐项验收

### 2.1 提示词与模型协议

| 验收项 | 结果 | 证据与原因 |
| --- | --- | --- |
| 消歧信息独立进入 `clarificationText`，不拼接到 `sourceText` | 通过 | `test/expressionQualityV13.contract.test.mjs` 解析实际模型消息，确认两个字段独立；渲染层不再存在 `sourceWithClarification` 或人工分隔标记。 |
| 原文字符数和输出预算不受消歧信息影响 | 通过 | 同一原文在有、无补充信息时的 `sourceCharacterCount` 与 `maxResultCharacters` 完全一致。 |
| IPC 全链路传递补充信息 | 通过 | renderer → preload → main → `enhancePrompt` 均有独立、最长 2000 字符的字段；原文继续作为替换事务的唯一 CAS 基线。 |
| 中文指令优先级完整 | 通过 | 已统一为“安全与输出协议 > 原文不可变事实与语义 > Recipe 目标 > 用户选择的档位 > 原文排版”。 |
| 中文协议语言一致 | 通过 | 中文系统提示词不再混入 `Scope policy`、`Semantic gate`、`Model-count gate` 等英文政策段落；技术字段名按协议保留。 |
| 补充信息只用于消歧 | 通过 | 首次生成和一次纠错重试都明确禁止把 `clarificationText` 并入正文、创建新任务或扩大范围。 |
| 专业档位禁止根据常识补造 | 通过 | “专业展开”只可重组原文已提供的信息，缺失项保持待确认；中英文合同均有对应约束。 |
| 既有安全校验不回退 | 通过 | 全量测试覆盖事实锚点、语义强度、范围、语言、长度、状态和单结果校验，172/172 通过。 |
| 20 轮提示词校准循环 | 通过 | `npm run qa:prompt-loop`：20/20 通过，范围扩散、语义升级、锚点丢失、创意超长、多候选等 bad case 均返回预期错误码。 |
| 真实模型协议 | 通过 | `deepseek-v4-flash` 两个真实调用用例通过；直接结果无二次改写包装，产品反馈未虚构 Word 等外部上下文。 |

## 4. 已知限制

- Electron 合成指针仍无法可靠完成窗口拖动和隐藏缩放柄的真实拖动，视觉 QA 将两项记为自动化限制，不是本轮产品缺陷；相关底层行为继续由单元与契约测试覆盖。
- 本轮没有实现实时输入监听、表达历史、个性化语气学习、自动发送或主观质量评分。这些方向需要新的隐私、数据和评估基础，不能在当前安全边界内直接推断为需求。
- 本轮没有重新生成 Windows EXE；若要发布安装包，应在当前源码签收后单独执行完整预打包闸门和产物校验。

## 5. 结论

本轮列出的提示词工程与界面优化项全部通过；未发现未通过项。当前实现更准确地区分原文与消歧上下文，模型约束与界面术语一致，用户也能在不增加高频步骤的前提下看懂本次表达优化的场景、档位、长度变化和校验状态。

# Prompt Lift project notes

- Keep Codex/Claude integration outside their app bundles. Capture the focused input with a saved target window, pass prompt text through the Windows clipboard, and apply changes only after a non-empty enhancement result is available.
- Keep PowerShell programs static and send user-controlled values as JSON on stdin; never interpolate prompt text into PowerShell source or command-line arguments.
- Keep the original prompt in main-process memory until the user restores or cancels the current operation. The renderer must keep late async results from applying after cancellation.
- The Electron preload must expose only named `prompt:*` operations through `contextBridge`; keep `nodeIntegration` disabled and `contextIsolation` enabled.
- Keep capture IPC canonical as `{ text, target }` while accepting legacy `{ original }` in the renderer; add a clipboard sentinel so a failed Ctrl+C cannot be mistaken for stale clipboard content.
- Keep model credentials out of source and logs. Persist them only through Electron `safeStorage` for the current Windows user, never as plaintext, and never include them in errors or packaged resources.
- Electron single-instance locking does not by itself prove there is only one `BrowserWindow`. Keep a local window reference inside lifecycle callbacks, clear the global reference only when it still points to that window, and reconcile against `BrowserWindow.getAllWindows()` before creating or showing the assistant.
- Windows text capture/replacement must use checked, atomic `SendInput` key sequences, wait until Alt/Ctrl/Shift are released, trigger double-Alt work on the second key-up, verify HWND plus PID, and restore the caret after clipboard-based verification.
- Treat model prompting as a versioned protocol, not prose: serialize source input as untrusted rewrite material, require a strict mode/language JSON envelope, reject truncation and reasoning pollution, and verify immutable anchors such as numbers, URLs, paths, and code tokens before replacement.
- Replacement is a compare-and-swap transaction: require the same HWND/PID, the captured original text, and a live operation token immediately before `SendInput`. Cancellation or stale content must never trigger a blind restore that could overwrite newer user edits.
- A title keyword may validate the focused target window but must never select the first arbitrary matching process. Preserve user clipboard updates by restoring only clipboard values still owned by Prompt Lift.
- Electron `ipcMain.handle` errors lose custom fields across `ipcRenderer.invoke`; wrap handler results in a small response envelope and revive `code`/`details` in preload so the UI can provide actionable recovery guidance.
- Keep compact and expanded pet states reversible: the close button hides to tray, while a dedicated collapse control only restores compact dimensions and preserves the current result/status.
- For TokenHub DeepSeek V4 compatible chat completions, send `thinking: { type: "disabled" }` so the final protocol JSON stays in `message.content`; never treat `reasoning_content` as user-facing output. If `finish_reason` is `length` with empty content, return a non-destructive truncation error.
- Validate persisted prompt modes against their values (`enhance` and `chat-polish`), not the camelCase keys used by the `PROMPT_MODES` object; regression-test both mode round trips and compact utility placement at the window edges.
- Evolve Prompt Lift as a safe Windows input-text action layer, not a general AI assistant. Prioritize preview/apply control, visible diffs, user-configured defaults, and additional whole-input-to-single-result recipes that reuse the existing CAS transaction; treat selection rewriting, conversation context, persistent history, and automatic sending as separate privacy-and-architecture projects.
- Organize Prompt Lift around three user-selected expression targets: AI prompts should clarify goals/context/constraints/output, upward communication should make conclusions and logic clearer, and end-user communication should be safer and more polite. Keep double-Alt zero-choice, remove proactive app-based recommendations, and implement any result iteration as one bounded internal self-check/rewrite that still returns a single final result.
- Treat PPT copy optimization as a whole-input recipe: turn descriptive titles into conclusion-led titles, compress body copy into one slide claim with clear hierarchy, and preserve all facts and anchors. Do not imply that the current bridge reads other text boxes, charts, notes, layouts, or an entire deck.
- Use a WeChat-like minimalist flat interaction language without copying WeChat brand assets: light neutral surfaces, restrained green emphasis, typography and separators for hierarchy, lightweight feedback, and no heavy gradients, glassmorphism, neon effects, thick shadows, or decorative AI animation.
- Keep model-side prompting modular and versioned: stable safety/protocol rules outrank immutable source facts and semantics, then Recipe goals, user-selected tiers, and untrusted `SOURCE_MATERIAL_JSON`; every Recipe must define one goal, hard/soft constraints, language and length policy, edge cases, output contract, and regression samples. Treat translation language overrides, broader semantic-anchor validation, and bounded second-pass rewriting as planned capabilities until their parser, validator, UI, and tests exist.
- Keep structured clarification separate from rewrite material end to end: `sourceText` remains the only body used for length, anchor, diff, and CAS checks, while a bounded `clarificationText` may only resolve references or ambiguity. Never concatenate clarification markers into source text or present user-edited results as model-validated.
- Differentiate prompt tiers with both explicit structure/length/expertise/creativity contracts and bounded model parameters. Keep repair retries deterministic, and do not reject a directly executable structured prompt merely because it preserves the source under a context label such as “用户反馈原文”.
- When the root exposes `data-mascot`, automated clicks must target `.mascot-option[data-mascot=...]` rather than an unscoped `[data-mascot]`, or the already-selected default can resolve to the root instead of the option button.
- Keep full UI QA and package-gate shortcut QA artifacts separate: full runs write `summary.json` / `UI_VISUAL_RESULTS.md`, while `--shortcut-only` writes `summary-shortcut.json` / `UI_SHORTCUT_RESULTS.md`. On Windows, retry only transient artifact-write lock codes with bounded backoff; never let a shortcut gate overwrite or contend with the full report.
- PowerShell event helpers with redirected stdout must explicitly set UTF-8 output and the Node parser must tolerate NUL-interleaved text. For a non-focusable desktop pet, snapshot the external foreground target on pointer entry and retain it briefly through the click so the assistant cannot replace the intended chat window during capture.
- Keep Prompt Pet inside one `BrowserWindow` and one main-card document flow: right-click is a zero-window mode toggle and the top-right ellipsis is the only menu entry, but the four-area function hub and its child settings are mutually exclusive pages rather than a vertically stacked long menu. Child pages return to the originating hub without losing task/result state; do not reintroduce secondary windows. When one control supports both drag-to-resize and click-to-open, suppress the click briefly after pointer movement so a resize never opens the menu.
- Do not use a presentation phase such as `loading` as the concurrency lock for shortcut workflows: double-Alt capture intentionally sets that phase before dispatching the captured payload. Guard enhancement with the real request identifier instead, and keep independent capture/model timeouts so every loading state has a terminal success or error path.
- A clickable Electron pet cannot rely on `app-region: drag`, because the draggable region suppresses pointer interaction. Use one-way `drag:start/move/end` IPC, resolve the window from absolute pointer displacement, coalesce move bursts to the latest point with one scheduled main-process update, and persist only on drag end.
- Reject model output that wraps the source as another rewrite request or leaks the system protocol. Retry that failure at most once with an explicit direct-result repair instruction, then preserve the original text; do not treat an ordinary `输出格式：` section by itself as a meta-prompt leak.
- Run the real-model delivery check inside Electron with Prompt Lift's actual `userData` path so `safeStorage` can decrypt the saved Key. Evidence may include endpoint, model, result length, and contract booleans, but never the Key, raw source, or complete model output.
- Treat double Alt as a release-gated event handoff: the main process sends `loading` before the captured payload, so the renderer must never discard that payload merely because it is already loading, and an unclaimed fresh capture must clear stale cancellation state. Every Windows package must run the real listener-liveness tests plus the isolated Electron `loading → captured → model → apply → terminal` flow, including cancel then retry.
- When review mode allows “auto-apply → edit → apply again”, keep the live CAS operation token until a new capture, cancellation, or restore invalidates the operation. Each subsequent apply must compare against the last text actually confirmed in the target; restore must also compare against that applied text, never against unsaved textarea edits.
- Visual QA for the single-scroll expanded assistant must distinguish true horizontal overflow from expected off-screen content inside the scrollable card. Before trusted clicks, scroll the target control into view; do not classify a long password/text input's native horizontal scrolling as clipped UI.
- Clipboard restoration is an ownership check in both capture and replacement flows: restore the prior clipboard only while the current value is still Prompt Lift's sentinel or captured/replacement value; a newer user clipboard value always wins, including on failure paths.
- Every fresh external capture starts a new CAS baseline, while regeneration and review edits stay inside the existing transaction and advance the baseline only after a replacement is confirmed.
- Body-language validation must be conservative and evidence-based: reject only a clear declared-language mismatch, ignore URLs, paths and code tokens, and allow short or technical mixed-language results when confidence is insufficient.
- Protocol status is a hard semantic contract: `unchanged` may be used only when `result` is byte-for-byte the source text; changed content with an unchanged label must fail before any replacement.
- Replacement authorization belongs to the Electron main process: bind each operation ID to a copied target identity, captured original, rolling confirmed CAS baseline, and bounded lifetime. Renderer apply/restore IPC may submit the operation ID and desired replacement only; it must never choose the target or trusted baseline.
- Windows packaging must audit the actual temporary `app.asar` before replacing the formal release: compare its exact runtime file set and per-source hashes with the reviewed workspace, reject development paths/metadata, symlinks and high-confidence secret literals, and keep raw archive separators for `statFile`/`extractFile` while using normalized paths only for policy checks.
- For transparent green-mascot cutouts generated on a magenta key, the shared chroma helper's soft matte/despill can misclassify warm fur and damage interior colors. Prefer a border-sampled hard key with a tested tolerance and 1-2 px alpha contraction, then verify on a light neutral composite plus RGBA/corner-alpha, interior-hole, and residual-magenta checks before delivery.
- Review-mode visual QA mocks must mirror the production `replace` contract and return `replaced: payload.replace !== false`; otherwise the mock falsely auto-applies review results and makes discard/apply action-state tests report a product regression that does not exist.
- A completed review action must not be enabled before its handler can accept it. In particular, discard is keyed to the visible completed review state rather than a request ID that may survive until the async `finally` microtask; trusted UI QA clicks must verify `elementFromPoint(...).closest(target)` before dispatch so a missed off-screen control cannot accidentally trigger the pet underneath.
- Keep the two work-mode entry paths distinct: choosing an item inside the mode panel returns to the parent menu and keeps the expanded view open, while the right-click mode cycle stays a zero-window compact shortcut. Pass that navigation intent explicitly instead of making `handleMode` always collapse or always expand.
- A transparent raster mascot that intentionally matches the CSS green knight must also bypass the generic photo frame: set its wrapper border and radius to zero, keep its background transparent, and allow visible overflow. Preserve the generic mode-colored frame for photographic mascots.
- 发布 Windows 便携包到 GitHub 时，保留当前发布目录和 ZIP，使用 Git LFS 跟踪大于 100 MB 的 EXE/ZIP，并忽略 `qa/evidence/ui/run-*` 与 `tmp/` 等生成物；README 必须说明用户要下载完整目录/ZIP，不能只运行孤立 EXE。
- Prompt Lift 的微信-like 体验应借鉴“稳定一级导航 + 分组列表 + 单页父子关系 + 状态可见性”，不要照搬聊天、朋友圈、支付或小程序。扩展功能中心使用“处理 / 场景 / 服务 / 我的”，双击 Alt 与小精灵单击仍保持零选择；视觉 QA 必须逐页打开四个 hub，并在 360×520 下确认身份栏、内容和落底导航同时完整可见。
- `context-menu button` 这类通用规则的 specificity 会覆盖 hub 内主按钮和摘要快捷块的颜色、网格和高度；新增例外控件时使用 `.context-menu .hub-primary-action` / `.context-menu .hub-summary-action` 明确重置，并以真实截图或 `getComputedStyle` 验证，不能只检查源 CSS 中是否出现目标声明。
- 功能中心调整信息归属时，必须同步更新视觉 QA 的 `actionHubs` 路由映射；“已配置”只表示存在可复用的加密凭据，不能替代独立的模型连接检查，也不能显示成“服务正常”。
- 功能中心的主操作必须感知未结束事务：审阅结果尚未应用时应续接现有结果，不能重新生成；模型设置同时区分“已保存凭据 / 当前编辑待保存 / 本会话连接检查”三类状态，并用可信点击断言续接前后模型调用数不增加。
- 系统提示词自定义应以“模式 × 档位”为键存放在 Electron `userData` 下的独立 JSON，采用临时文件写入后原子替换；UI 展示默认/生效只读文本，用户只编辑有长度上限的低优先级补充规则，且主进程再次校验模式、档位和长度，避免把用户自定义规则提升为安全协议。
- UI 几何审计遇到滚动容器时，元素矩形必须按所有 `overflow: hidden/clip/auto/scroll` 祖先裁剪后再做越界与重叠判断；直接使用完整 `getBoundingClientRect()` 会把被滚动裁掉的内容误报为覆盖固定标题。

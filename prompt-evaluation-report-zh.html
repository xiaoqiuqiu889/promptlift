二、我改了什么

改动分为“运行时提示词合同、真实模型评测、无上限质量度量、连续门禁、测试与报告”五层，目标是让模型输出变化可复现、可解释、可阻断。

改动具体内容直接价值
统一长度约束创意档位从原来的 350% 改为 300%；所有档位使用原文字符数的严格相对上限；移除短文本遗留的 1200 字符下限。任何档位都不能通过短原文绕过长度约束。
压缩系统提示词把模型侧 system message 收敛为“协议 → 原文事实 → 模式 → 档位 → 输出合同”，去掉重复解释，但保留锚点、状态、scope、语气和 JSON 闸门。减少模型输入负担，同时不牺牲安全和原文保真。
接入真实模型评测新增 TokenHub runner，真实调用 deepseek-v4-flash；候选与 baseline 使用同一批 16 条样例；另用真实模型做 blind pairwise judge。报告结论不再来自 mock 或人工编造。
质量分改为无上限评级保留 bounded qualityScore 作为合规信号；新增无上限 qualityRating，由真实模型的胜/平/负比较计算。1.000 饱和不再掩盖真实质量变化。
连续两次门禁新增 streak state、重复采样和 Wilson 置信下界；只有连续两轮通过才具备晋级资格。避免一次偶然的模型波动触发写回。
隐私与分支隔离摘要只保留计数、比率、失败类别、哈希和时间戳；Key、原文和模型全文不落盘；所有改动只在独立 worktree。评测过程不污染主进程，也不泄露敏感数据。

原文优先原则

  • 非创意档位不新增应用场景、平台、受众、交付物或承诺。
  • 创意档位只增加受控、可比较、服务原任务的方向。
  • URL、路径、数字、Issue ID、代码和模板变量必须保留。
  • 否定、建议、可能性等语气强度不能被模型擅自升级或解除。

三、现在如何量化

硬指标：先判定能不能用

  1. 协议字段、mode、language、status 完整且语义正确。
  2. 结果长度不超过原文的 300%。
  3. 锚点召回率、负向约束、软硬语气不退化。
  4. 不得凭空引入平台、受众、流程、能力或应用场景。

无上限质量评级：再比较哪个好

每个对齐样例由真实 judge 返回候选胜、平或 baseline 胜：

effectiveWins = wins + 0.5 × ties
p = (effectiveWins + 1) / (comparisons + 2)
ratingDelta = 400 × log10(p / (1 - p))
qualityRating = 1000 + ratingDelta

评级没有人为上限。晋级还要求 ratingDelta ≥ 20、Wilson 95% 下界大于 0，并且硬指标和受保护指标不回退。

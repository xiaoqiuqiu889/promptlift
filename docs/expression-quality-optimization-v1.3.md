# Prompt Lift「一起让表达变好」优化方案 v1.3

## 1. 目标

围绕“一起让表达变好”，把一次处理收敛成可验证的闭环：

1. 正确理解原文与必要补充信息。
2. 按当前表达场景和优化档位完成一次受约束的直接改写。
3. 让用户看懂结果发生了什么，并保留审阅、编辑、应用和恢复的控制权。
4. 不增加高频路径步骤，不扩大输入监听、历史记录或自动发送范围。

## 2. 评估方法

本次只记录能够从当前代码、界面或既有回归用例中复现的问题。优先级按“对表达质量的直接贡献 × 出错影响 × 开发成本”确定：

- **P0**：可能改变模型理解、原意或安全应用结果，必须优先修复。
- **P1**：影响用户理解与操作判断，修复后可明显降低认知负担。
- **P2**：有价值但需要新的隐私、协议或数据基础，不在本轮贸然实现。

| --- | --- | --- | --- |

## 4. 产品界面与交互优化

| 问题描述 | 改进建议 | 优先级 | 预期效果 |
| --- | --- | --- | --- |
| 产品核心目的没有在主界面形成稳定、轻量的品牌承诺。 | 在主身份区加入“一起让表达变好”，操作方法继续放在状态提示和帮助页，不增加点击步骤。 | P1 | 用户一眼理解产品价值，而不是只看到工具操作。 |
| 安全校验失败时提示用户切换“严格保真”，但当前可见档位名称是“原意守护”。 | 所有界面错误提示统一使用当前档位名称“原意守护”。 | P0 | 用户能够直接找到对应选项，避免死路文案。 |
| 复制反馈仍使用“增强结果”，无法覆盖用户沟通、向上沟通和 PPT 文案场景。 | 统一使用“优化结果”或“表达结果”等跨场景术语。 | P1 | 四种场景的界面语言一致，不把所有任务误称为提示词增强。 |
| 结果页只有字符数与差异，没有把场景、档位、安全状态和长度变化汇总在一起。 | 增加本地生成的“本次优化”摘要：当前场景、当前档位、原文与结果字符数、安全校验状态。摘要只展示可验证事实，不生成主观质量分。 | P1 | 用户无需在多个区域来回确认，可更快决定应用、编辑或放弃。 |
| 补充信息重新生成时临时强制审阅，但界面没有明确说明补充信息只用于消歧。 | 调整输入说明和按钮文案，明确“补充内容不会并入原文”；重新生成后仍先审阅。 | P1 | 降低用户担心补充说明污染正文的顾虑，同时保持安全控制。 |

## 5. 本轮不实现的方向

| 方向 | 处理结论 | 原因 |
| --- | --- | --- |
| 实时监听任意输入框并持续给建议 | 暂缓，列为 P2 独立项目 | 需要持续输入监听、节流、隐私告知和新的一致性事务，不属于当前一次捕获—一次结果架构。 |
| 保存表达历史、跨会话学习个人语气 | 暂缓，列为 P2 独立项目 | 当前承诺“不保存输入内容或优化历史”；实现前需要新的数据授权、加密、清除和迁移设计。 |
| 自动发送或自动接受模型结果 | 不采用 | 会削弱审阅、编辑、恢复与 compare-and-swap 安全边界。 |
| 主观“表达质量评分” | 暂不采用 | 当前没有可信标注集和可解释评分基线；用未校准分数会制造虚假确定性。 |

## 6. 开发范围

### 6.1 模型协议

- `sourceText`：唯一待改写正文。
- `clarificationText`：可选、最长 2000 字符的消歧上下文。
- `sourceCharacterCount` 与 `maxResultCharacters`：只基于 `sourceText` 计算。
- 所有字段通过 JSON 序列化传递，不插入系统提示词或命令行。
- 结果继续使用单 JSON、单最终文本、一次可控纠错重试和既有安全校验。

### 6.2 界面

- 不改变双击 Alt 与单击小精灵的高频零选择路径。
- 结果摘要只使用本地已有状态，不增加模型调用。
- 不修改四种场景、四个档位、审阅后应用、恢复原文和安全回填的既有结构。
- 保持微信-like 的浅色、扁平、克制绿色设计，不增加渐变、重阴影或装饰动画。

## 7. 验收标准

### 7.1 提示词与模型协议

- [ ] 消歧补充信息独立进入 `clarificationText`，不再拼接到 `sourceText`。
- [ ] `sourceCharacterCount` 与长度上限只按原文计算。
- [ ] 中文指令优先级包含“原文不可变事实与语义”，且中文档位政策不混入英文规则。
- [ ] 系统提示词明确补充信息只用于消歧，不得并入正文、创建新任务或扩大范围。
- [ ] 专业档位明确禁止根据常识补造信息；缺失信息只保留为待确认。
- [ ] 现有事实锚点、语义强度、范围、语言、长度和单结果校验全部继续通过。

### 7.2 界面与交互

- [ ] 主界面可见“一起让表达变好”。
- [ ] 安全错误提示使用“原意守护”，不再出现已废弃的“严格保真”。
- [ ] 复制成功与失败反馈使用跨场景的“优化结果”术语。
- [ ] 生成结果后展示场景、档位、字符变化和“安全校验通过”四类可核验信息。
- [ ] 编辑结果时字符变化实时更新，不增加额外模型请求。
- [ ] 补充信息区域明确说明“只用于消歧，不会并入原文”。

- [ ] 全量单元与契约测试通过。

- [ ] 视觉 QA 在完整与小窗口视图下均无越界、遮挡或流程缺陷。

# Prompt Lift 微信-like 第 11–15 轮自主优化报告

## 目标与产品边界

本轮在既有“处理 / 场景 / 服务 / 我的”四区结构上继续优化，学习微信类成熟产品的三个核心体验：状态连续、信息可信、身份一致。Prompt Lift 的本质仍是“Windows 任意输入框里的安全表达助手”，核心目的仍是“一起让表达变好”。

没有照搬聊天、朋友圈、支付或小程序：

- 聊天与朋友圈需要账号、关系链、内容历史和同步，不是完成一次安全表达优化所必需。
- 支付会引入交易与合规责任，与文本处理链路无关。
- 小程序式能力中心会扩散产品范围，增加高频操作的选择成本。
- 本轮新增能力全部复用现有优化、审阅、模型检查和小精灵状态，不创建第二套任务或数据系统。

## 基线诊断

第 6–10 轮已经建立主操作、快捷设置、任务状态、隐私归类和凭据状态，但真实流程仍存在五个可提升点：

1. 有待审阅结果时，从功能页点击主按钮会重新生成，可能丢失当前审阅上下文。
2. “审阅后应用”和“直接回填”的差异只存在于设置值，主操作附近缺少即时说明。
3. “已配置”只能说明凭据已保存，不能说明当前会话已经连接成功。
4. 编辑模型配置后，一级页面仍可能显示旧状态，用户不知道改动尚未保存。
5. “我的”页使用固定身份图形，未跟随当前小精灵，视觉身份不连续。

## Loop 11：待审阅任务可安全续接

### 具体改动

- 增加 `hasPendingReview()`，只在“审阅模式开启 + 已有非空优化结果 + 尚未确认应用”时成立。
- 功能页主按钮在该状态下显示“继续审阅”。
- 点击后返回已有结果，不重新调用模型、不清空编辑内容、不创建新操作。
- 顶部状态同步显示“待审阅”，副文案明确“返回本次结果，不会重新生成”。

### 理由

成熟产品的一级入口必须理解当前任务，而不是每次都创建新任务。对 Prompt Lift 来说，待审阅结果是一个尚未结束的安全事务，应优先续接。

### 效果评估

- 从功能页返回审阅结果仍为 1 次点击。
- 模型 `enhance` 调用次数在续接前后保持不变。
- 原始文本、优化结果和 CAS 应用事务均被保留。
- 自动化证据：`expanded-review-hub-continue`、`expanded-review-resumed-without-regenerate`。

## Loop 12：把当前应用策略放到主操作旁

### 具体改动

- 审阅模式开启时显示“只处理当前输入 · 不保存表达历史 · 先审阅再决定回填”。
- 直接回填模式显示“只处理当前输入 · 不保存表达历史 · 通过校验后安全回填”。
- 文案由现有 `reviewMode` 状态实时更新，不推断尚未实现的隐私能力。

### 理由

用户点击主操作前最需要确认的是“结果会不会直接写回”。把应用策略放在主按钮旁，比只在设置项中展示更能降低误操作焦虑。

### 效果评估

- 用户无需进入设置即可知道本次应用策略。
- 审阅与直接回填的差异从配置层提升为操作前反馈。
- 文案继续准确表达已实现的本地保护、校验和回填边界。

## Loop 13：拆分“凭据状态”和“连接状态”

### 具体改动

- “模型与 Key”继续显示凭据状态：已配置、待配置、仅本次。
- “检查模型配置”独立显示当前会话连接状态：未检查、检查中、已连接、检查失败。
- 连接检查开始、成功和失败时即时更新一级页面。

### 理由

凭据已保存不等于网络、模型和 Key 当前可用。将两类事实分开，避免使用“正常”之类过度承诺的笼统状态。

### 效果评估

- 用户在“服务”页即可区分“已经保存”和“已经验证”。
- 检查失败不会覆盖凭据是否已保存的事实。
- 状态变化使用 `aria-live="polite"`，兼顾屏幕阅读器反馈。

## Loop 14：模型配置改动进入“待保存”状态

### 具体改动

- Endpoint、模型名、API Key 或目标窗口规则发生变化时，立即标记 `modelConfigDirty`。
- 配置页显示“配置已修改，保存或检查后生效”。
- “服务”页的凭据状态显示“待保存”，连接状态回到“未检查”。
- 保存成功或“检查并保存”成功后清除待保存状态。

### 理由

成熟设置体验必须区分“正在编辑的值”和“已经生效的值”。如果一级页面继续展示旧状态，用户会误以为修改已经保存。

### 效果评估

- 编辑、保存、检查三种状态形成可见闭环。
- 不新增自动保存，避免未经用户确认就持久化 Key 或地址。
- 自动化分别验证了“待保存 / 已连接 / 检查失败”三个一级状态。

## Loop 15：小精灵身份跨页面保持一致

### 具体改动

- “我的”页头像跟随当前小精灵：
  - 可卡布犬：显示当前透明 PNG；
  - 绿色骑士小狗：显示当前透明 PNG；
  - CSS 绿色骑士：复用同一套 CSS 骑士结构并按头像尺寸缩放。
- 切换小精灵后，顶部头像、紧凑态角色和个人页头像同步变化。
- 不复制新的图片资产，也不增加边框式角色底图。

### 理由

微信类成熟体验强调身份在不同页面中的连续性。Prompt Lift 虽然没有账号系统，但当前小精灵就是本地表达伙伴的可见身份。

### 效果评估

- 三种小精灵均通过真实图片解码或 CSS 语义验收。
- 视觉复核发现初版 CSS 骑士使用了“骑”字占位，随后替换为真实缩放骑士图形。
- 个人页与顶部身份保持一致，同时继续使用极简扁平容器。

## 最终体验结构

| 一级入口 | 用户问题 | 本轮强化 |
| --- | --- | --- |
| 处理 | 当前任务进行到哪一步，点击后会发生什么？ | 待审阅续接、动态应用策略、避免重复生成 |
| 场景 | 这次面向谁表达？ | 保持四种表达场景，不增加无关模块 |
| 服务 | 配置保存了吗，当前连接验证了吗？ | 凭据、待保存和会话连接三类状态分离 |
| 我的 | 当前表达伙伴是谁，数据如何处理？ | 小精灵身份同步、隐私与安全入口 |

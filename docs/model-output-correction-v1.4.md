# 模型输出纠偏与验收报告 v1.4

## 结论

本轮采用“真实模型预测 + 运行时闸门 + 30 项逐条契约测试”三层验收，不以代码阅读或模拟响应代替真实模型结果。

- 真实模型：`deepseek-v4-flash`
- 真实接口：当前应用已保存的 TokenHub OpenAI-compatible 配置
- 全矩阵：4 个场景 × 4 个档位 × 中英文，共 32 次真实预测
- 最终结果：32/32 通过；28 次首轮通过，4 次经第 1 次定向纠偏后通过，0 次进入第 2/3 次纠偏，0 次失败回填；所有样本总调用次数均未超过 4
- 稳定性复测：英文创意高波动组合最新 13/13、中文 PPT 简洁档最新 8/8、英文 AI 简洁档最新 5/5；此前编号产品反馈 5/5、英文 PPT 简洁档 3/3
- 协议：所有真实返回均为单个合法 JSON、字段精确、协议版本一致
- 隐私：报告不保存 API Key、原始输入或完整模型结果

真实迭代并非一次通过：早期全矩阵曾出现 13/32、25/32、29/32、30/32、31/32；在最终源码复跑阶段又真实记录到 31/32、31/32、30/32、31/32，最近三次完整复跑也分别因 `needs_input`、PPT 锚点丢失和交付物漂移停在 31/32。独立真实契约还曾暴露编号产品反馈被概括成“三个问题”。逐项复现后修复了日期缩写、URL 泛称、交付物误判、明确否定弱化、虚构量化刻度、JSON 协议漂移、PPT 语气漂移、普通缺口滥用 `needs_input` 及编号反馈过度压缩，最终全矩阵 32/32、独立真实契约 3/3。失败轮次没有被改写为通过。

## 纠偏架构

1. 系统提示词只保留紧凑的稳定协议、场景合同、档位合同和一行语义闸门。
2. 每次请求携带精确字符上限；创意档最多两个单句建议方向。
3. 模型输出先通过 JSON、状态、语言、长度、事实锚点、语义强度、任务对象和范围校验。
4. 所有档位温度为 0；档位差异由各自内容合同决定。可修复错误最多重试 3 次，每次只追加当前失败原因和必要细节。
5. 仍不合格时保留原文，绝不覆盖用户输入。
6. 对 `August 6 → Aug 6` 这类唯一、无歧义的格式缩写做确定性锚点回收；真实事实缺失进入有界纠偏循环。
7. API 请求使用 JSON Object 输出约束；PPT 结果若遗漏原文中的建议、可能性或明确否定，只回收原文对应短句，不生成新事实。
8. 编号产品反馈允许重排序号，但若模型概括掉具体功能名或界面动作，只把原文对应编号行原样补回。
9. 仅在纠偏请求中提供一行短错误焦点：轮次、错误码、问题说明及必要锚点或范围类别；不把这些细节塞进常驻系统提示词，也不重复累计旧错误。
10. 单一 URL 被改成“给定仓库路径”等泛称时，运行时只回收原 URL；交付物校验只识别明确输出动词后的对象，避免把“代码、测试、界面证据”等审计输入误判成交付物。

## 提示词长度控制

没有把 30 条问题逐条塞入系统提示词。新增内容集中为：

- 常规请求：一行锚点 / 交付物 / 否定 / 语气联合约束；
- 每次请求：一行动态字符预算；
- 仅纠偏时：一行“纠错轮次 + 错误码 + 当前问题 + 必要细节”。

其余风险由解析器、验证器、最多 3 次有界纠偏和回归集承担，避免系统提示词持续膨胀。
